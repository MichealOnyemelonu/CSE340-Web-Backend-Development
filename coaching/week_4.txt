Great question — this gets right at the heart of why sessions + flash messages exist.

Answer (concise and clear)
You use req.flash() because you need a way to carry a message across a redirect, which is something you cannot do directly 
in the normal request–response cycle. After a redirect, the original response is gone, so flash messages store the message temporarily in 
the session and make it available on the next request.

What problem this solves
In your flow:

await createCategory(category_name);
res.redirect('/categories');

The redirect creates a new HTTP request, so:

You cannot send a message in the same response
Anything like res.send() or res.render() would be lost

Why flash messages are needed
Flash messages solve this by:

Storing the message in the session
Persisting it for one request only
Automatically clearing it after it’s displayed

Simple way to think about it


Without flash:
👉 “I want to tell the user something, but I have to redirect them — so the message disappears.”


With flash:
👉 “I store the message temporarily, redirect, and then show it on the next page.”

Bottom line
You weren’t just adding a message — you were solving the problem of communication across redirects in a stateless HTTP cycle.

This shows:

Validation rules are defined separately
The controller checks results before proceeding
Errors are handled before touching the database

What this accomplishes

Prevents invalid data from reaching your database
Ensures user input follows rules (required, length limits)
Provides feedback without crashing the app

One important insight
Notice how validation happens before this line:

await createCategory(category_name);

That ordering is critical — it protects your model and database from bad input.
